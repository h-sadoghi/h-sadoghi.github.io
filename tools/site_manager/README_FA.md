# راهنمای سادهٔ مدیریت محتوای محلی سایت

## اجرا

1. روی `RUN_SITE_MANAGER.cmd` دوبار کلیک کنید.
2. در اولین اجرا، محیط Python و بسته‌های لازم ساخته می‌شوند؛ اینترنت فقط برای همین نصب اولیه لازم است.
3. مرورگر در `http://127.0.0.1:8765` باز می‌شود. ابزار فقط روی همین رایانه در دسترس است.

## افزودن محتوا

1. «افزودن مطلب» را انتخاب کنید.
2. بخش مقصد یا درس، عنوان، فایل Markdown و تصویر/PDFها را انتخاب کنید.
3. «پیش‌نمایش قبل از ذخیره» را بزنید و وضعیت نهایی را ببینید.
4. «تأیید و ذخیره در مخزن محلی» را بزنید.

Slug، مسیر، permalink، layout و Front Matter خودکار ساخته می‌شوند. مطلب تازه به‌صورت پیش‌فرض آمادهٔ انتشار پس از Push و Merge است؛ برای پیش‌نویس، «تنظیمات پیشرفته» را باز کنید. برای ویرایش، از «مطالب موجود» جست‌وجو و «ویرایش» را انتخاب کنید. عنوان، متن و وضعیت فعلی بارگذاری می‌شوند و وضعیت انتشار تا تغییر صریح شما حفظ می‌شود.

برای ساخت درس، «درس جدید» را باز کنید و عنوان، توضیح اختیاری، فصل‌ها و در صورت تمایل یک تصویر را وارد کنید. پیش‌نمایش، صفحه درس و رکورد تصویری آن در صفحه Teaching را با هم نشان می‌دهد. پس از ذخیره، درس تازه به فهرست تصویری Teaching و مقصدهای «افزودن مطلب» اضافه می‌شود. اگر تصویری انتخاب نکنید، تصویر استاندارد `assets/img/courses/default-course.svg` استفاده می‌شود. هر ذخیره یک پشتیبان محلی در `.site-manager-backups/` می‌سازد و در صورت خطای نوشتن، همه اجزای همان عملیات بازگردانده می‌شوند. ابزار Commit یا Push نمی‌کند.

برای تغییر تصویر یک درس موجود، در همان بخش «درس جدید»، گزینهٔ «تغییر تصویر یک درس موجود» را باز کنید. این کار رکورد یا صفحهٔ تازه نمی‌سازد و تصویر قبلی را نیز حذف نمی‌کند.

اطلاعات همه درس‌ها در `_data/teaching_courses.yml` نگهداری می‌شود. هر رکورد شناسه، عنوان، توضیح، تصویر، URL، ترتیب، نوع لینک، فصل‌ها و وضعیت انتشار دارد؛ بنابراین افزودن درس به ویرایش دستی `_pages/teaching.md` نیاز ندارد.

## بسته‌های ZIP فصل‌های درس

درس Image Processing سه صفحهٔ ثابت دارد: صفحهٔ ورودی `/teaching/image-processing/`، فایل‌های فصل Gonzalez در `/teaching/image-processing/gonzalez/` و آثار دانشجویی در `/teaching/image-processing/student-work/`. صفحهٔ ورودی فقط معرفی و پیوند این دو بخش را نمایش می‌دهد.

در بخش «افزودن مطلب»، گزینهٔ «افزودن بسته ZIP یک فصل به درس» را باز کنید. درس، مجموعه آموزشی، شماره، عنوان و در صورت نیاز خلاصه فصل را وارد کنید و ZIP را بدهید؛ PDF مشاهده مستقیم اختیاری است. اطلاعات مجموعه‌ها در `_data/teaching_packages.yml` و فایل‌ها بدون استخراج در `assets/downloads/courses/` ذخیره می‌شوند. فصل‌های Gonzalez به‌صورت خودکار در صفحهٔ Gonzalez نمایش داده می‌شوند.

برای جایگزینی ZIP یک فصل موجود باید گزینهٔ «جایگزینی آگاهانه» را صریحاً فعال کنید. نسخه قبلی قبل از نوشتن در `.site-manager-backups/` نگهداری می‌شود. ZIP و PDF هرکدام حداکثر ۵۰ مگابایت هستند؛ GitHub برای فایل بزرگ‌تر از ۵۰ MiB هشدار می‌دهد و فایل بزرگ‌تر از ۱۰۰ MiB را در Git عادی رد می‌کند. Git LFS نیز برای GitHub Pages قابل استفاده نیست. اندازه کل سایت منتشرشده در GitHub Pages باید زیر ۱ GB بماند؛ بنابراین با افزودن فصل‌های حجیم، اندازه Build را دوره‌ای کنترل کنید. مسیرهای ناامن، ZIP رمزگذاری‌شده، symlink، فایل جعلی و ساختارهای مشکوک به ZIP bomb پذیرفته نمی‌شوند.

برای ثبت تکلیف یا پروژه، «افزودن تکلیف یا پروژه دانشجویی» را باز کنید. عنوان، خلاصه، ZIP و در صورت نیاز نام دانشجو، نیمسال و PDF را وارد کنید. ثبت تنها زمانی ممکن است که تأیید مالک را صریحاً فعال کنید. داده‌ها در `_data/teaching_student_works.yml` و فایل‌ها در مسیر امن همان درس ذخیره می‌شوند؛ عنوان و مسیر تکراری پذیرفته نمی‌شود.

کاربر متخصص در صورت نیاز می‌تواند سه صفحه را در `_pages/courses/image-processing*.md`، فهرست فصل‌ها را در `_data/teaching_packages.yml`، آثار دانشجویی را در `_data/teaching_student_works.yml` و قالب مشترک را در `_includes/teaching_course_materials.liquid` بازبینی کند. برای کار روزانه ویرایش دستی این فایل‌ها لازم نیست.

## پیش‌نمایش

«پیش‌نمایش سریع Markdown» بدون Ruby کار می‌کند. دکمهٔ «اجرای پیش‌نمایش Jekyll» سایت واقعی را روی `http://127.0.0.1:4000` می‌سازد و پس از آماده‌شدن در مرورگر باز می‌کند. پیش‌نویس‌های دارای `published: false` نیز فقط در این پیش‌نمایش محلی دیده می‌شوند و وضعیت انتشار فایل تغییر نمی‌کند.

اولین ساخت ممکن است چند دقیقه طول بکشد. وضعیت و انتهای لاگ در همان صفحه نمایش داده می‌شود. اگر سرور از قبل به‌وسیلهٔ Site Manager اجرا شده باشد دوباره استفاده می‌شود؛ اگر برنامهٔ دیگری پورت 4000 را گرفته باشد پیام خطای روشن می‌بینید. برای آزادکردن پورت از دکمهٔ «توقف Jekyll» استفاده کنید.

## GitHub Desktop پس از ذخیره

1. مخزن `J:\SadoghiSite2\h-sadoghi.github.io` و شاخهٔ feature درست را در GitHub Desktop انتخاب کنید.
2. همهٔ Changes و diffها را بازبینی و سپس Commit محلی کنید.
3. با حساب دارای مجوز مخزن `h-sadoghi/h-sadoghi.github.io`، شاخهٔ جاری را با دکمهٔ `Publish branch` یا `Push origin` ارسال کنید.
4. آزمون‌های GitHub Actions را بررسی کنید و فقط پس از تأیید مالک تغییرات را به `master` ادغام کنید.

## خط فرمان و API کوچک

اجرا: `python -m tools.site_manager --repo J:\SadoghiSite2\h-sadoghi.github.io`

کلاس `tools.site_manager.SiteManager` متدهای `preview_add`, `add`, `preview_edit`, `edit` و `validate` را برای کارهای دسته‌ای ارائه می‌کند. عملیات نوشتن به `confirm=True` و یک Preview بدون خطا نیاز دارد.
